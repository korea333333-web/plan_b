# 품질 기준 — 현재 MVP

## 1. 기본 게이트

```bash
pnpm run lint
pnpm run build
pnpm test
pnpm exec next build
```

`pnpm test`와 `pnpm run build`는 vinext·Sites 경로를 확인한다. `pnpm exec next build`는 Vercel용 Next.js 빌드 경로를 확인한다.

## 2. 현재 자동 테스트 범위

`tests/planner-engine.test.mjs`:

- 윤년을 포함한 날짜 더하기
- 월요일 시작 주간 날짜
- 날짜 범위 검증
- 자동 계획의 선택 요일·시간·하루 한도
- 겹치는 가능 시간 병합
- 부족한 분량 반환
- 종료 전 planned와 종료 후 unconfirmed 계산
- 판정된 일정만 사용하는 전체 완료율
- 일정이 있는 날 기준 연속 달성
- 화산오검 순환과 확정 대사

`tests/rendered-html.test.mjs`:

- production worker가 200 HTML을 반환
- 제목과 세 탭 라벨
- 초기 로딩 문구
- 친구 메뉴 부재
- 빈 상태 문구
- 시안용 예시 일정 부재
- 핵심 확정 대사가 엔진에 존재

현재 자동 테스트에 없는 것:

- 실제 D1 CRUD 통합 테스트
- Vercel `localStorage` CRUD 통합 테스트
- 브라우저 상호작용 E2E
- 시각 회귀
- 로그인·다중 사용자·교차 기기 테스트
- 자동 생성 저장의 롤백 테스트
- 월간 통계 테스트

없는 기능을 통과 조건처럼 문서화하지 않는다.

## 3. 필수 수동 스모크 테스트

### 로컬·Sites의 빈 상태와 D1 저장

1. 새 `clientId`로 접속한다.
2. `아직 계획이 없습니다.`와 `계획 만들기`를 확인한다.
3. 직접 계획 한 건을 저장한다.
4. 새로고침 후 같은 브라우저에서 계획이 다시 로드되는지 확인한다.
5. 다른 브라우저 프로필에서는 같은 계획이 보이지 않는지 확인한다.
6. D1 API를 끊었을 때 브라우저 저장 안내와 `서버 다시 연결`이 나타나는지 확인한다.

이 테스트는 D1 서버 저장을 확인하지만 교차 기기 동기화를 확인하는 테스트가 아니다. 다른 브라우저에는 같은 `clientId`가 없기 때문이다.

### Vercel의 브라우저 저장

1. Vercel 배포에서 빈 상태로 시작한다.
2. 직접 계획과 자동 계획을 저장하고 새로고침해 유지되는지 확인한다.
3. 완료·미완료 변경과 삭제가 새로고침 후 유지되는지 확인한다.
4. DevTools에서 계획이 현재 origin의 `localStorage`에 있는지 확인한다.
5. 다른 브라우저 프로필에서는 계획이 보이지 않는지 확인한다.
6. 네트워크를 끊어도 기존 브라우저 계획을 읽을 수 있는지 확인한다.
7. 사이트 데이터를 지운 뒤 계획이 사라지는지 확인한다.

Vercel 테스트에서 D1 행 생성이나 서버 동기화를 기대하면 안 된다.

### 보기 전환

1. 이전·다음 주가 이동하는지 확인한다.
2. 30분/1시간 변경 시 일정 시간이 바뀌지 않는지 확인한다.
3. 오늘의 표/원 보기가 같은 일정 집합을 표시하는지 확인한다.
4. 일정 카드를 눌러 상세 시트를 열고 삭제해 본다.

### 직접·자동 작성

1. 끝 시간이 시작 시간보다 빠른 직접 계획을 거부하는지 확인한다.
2. 반복 요일 계획이 기준일 이후 해당 요일에 나타나는지 확인한다.
3. 자동 생성에서 할 일, 기간, 요일, 가능 시간, 하루 한도를 입력한다.
4. 미리보기와 부족 분량 경고를 확인한다.
5. 저장 후 생성된 항목이 계획표에 나타나는지 확인한다.

로컬·Sites 자동 저장은 순차 POST다. 네트워크를 중간에 끊어 일부 D1 저장이 남을 수 있음을 현재 제한으로 취급한다. Vercel은 브라우저 저장 경로이므로 별도로 새로고침 영속성을 확인한다.

### 판정과 기록

1. 종료 전 일정은 `예정`이고 판정 버튼이 없는지 확인한다.
2. 종료된 미판정 일정에 `미확인`과 `뭐야, 왜 안 왔어?`가 보이는지 확인한다.
3. 완료·미완료 판정 후 순서에 맞는 토스트 대사를 확인한다.
4. 새로고침 후 반응 순번이 청명부터 다시 시작하는지 확인한다.
5. 전체 완료율이 완료/(완료+미완료)인지 확인한다.
6. 기록 탭에 전체 완료율, 연속 달성, 미확인, 미완료, 최근 6개가 보이는지 확인한다.

## 4. 반응형 점검

점검 화면:

- 320×568
- 390×844
- 768×1024
- 1440×900

확인:

- 920px 이하에서 모바일 헤더와 하단 내비게이션이 나온다.
- 920px 초과에서 좌측 사이드바가 나온다.
- 하단 내비게이션이 저장 버튼과 본문을 가리지 않는다.
- 주간표 가로 스크롤은 `.weekly-scroll` 안에서만 발생한다.
- 620px 이하에서 원형 그래프, 폼, 기록이 세로로 정리된다.
- 긴 제목과 메모가 카드 바깥으로 넘치지 않는다.
- 상세 시트와 반응 토스트가 하단 내비게이션 위에 보인다.

## 5. 접근성·모션 최소 확인

현재 MVP에서 반드시 유지할 항목:

- 입력과 버튼의 `focus-visible` 윤곽
- 아이콘 또는 X 단독 버튼의 한글 `aria-label`
- 원형 그래프 옆의 텍스트 범례
- 상태의 색상 + 한글 라벨
- 장식 꽃잎의 `aria-hidden`과 `pointer-events: none`
- `prefers-reduced-motion`에서 꽃잎 숨김

포커스 트랩, Escape로 상세 시트 닫기, 완전한 스크린리더 대화상자 의미는 현재 구현되지 않았다. 이를 구현하기 전까지 준수했다고 주장하지 않는다.

## 6. 콘텐츠 회귀 점검

배포 전에 검색한다.

- 친구, 동문, Roster, Invite가 제품 UI에 없는가
- 검술 수련, 명상, 서예 같은 Stitch fixture가 없는가
- Googleusercontent 등 Stitch 원격 이미지 URL이 없는가
- 확정 대사가 `lib/planner.ts`와 일치하는가
- 핵심 사용자 문구가 한국어인가

## 7. 현재 알려진 제한

- 브라우저 `clientId`는 인증이 아니다.
- 어느 환경도 다른 기기와 동기화되지 않는다.
- 로컬·Sites에서는 localStorage의 `clientId`를 지우면 기존 D1 계획을 다시 찾을 방법이 없다.
- Vercel에서는 계획 자체가 localStorage에만 있어 사이트 데이터를 지우면 사라진다.
- Vercel 저장은 D1 저장이나 서버 백업이 아니다.
- 로컬·Sites의 자동 계획 저장은 부분 성공할 수 있다.
- 반복 계획은 회차별 판정이 아니다.
- 판정 정정과 일정 내용 편집 UI가 없다.
- 보기 설정과 반응 순번은 저장되지 않는다.
- 기록은 전체 행 집계이며 주간·월간 통계가 아니다.
- 실제 D1과 브라우저 흐름은 아직 자동 통합 테스트가 없다.
