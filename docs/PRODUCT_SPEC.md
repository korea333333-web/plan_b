# 제품 명세 — 현재 MVP

## 1. 제품 정의

**매화수련록**은 계획을 직접 적거나 간단한 규칙으로 자동 분배하고, 종료된 일정의 실행 여부와 누적 기록을 확인하는 개인용 웹 계획표다.

현재 제품은 Google 계정으로 로그인해야 사용할 수 있다. Supabase Auth가 Google OAuth 세션을 관리하고, 모든 배포 환경은 Supabase의 같은 계획 저장소를 사용한다. 같은 Google 계정으로 로그인하면 모바일과 PC, 서로 다른 브라우저에서 계획과 수련 기록을 이어 볼 수 있다.

## 2. 화면 구조

로그아웃 상태에서는 `Google로 계속하기` 화면을 표시한다. 로그인 뒤 `/` 한 페이지 안에서 다음 세 탭을 전환한다.

1. **내 계획표**
2. **계획 만들기**
3. **수련 기록**

페이지를 새로고침하면 첫 탭인 내 계획표로 돌아온다. 별도 `/create`, `/records` 주소나 브라우저 뒤로가기 이력은 없다.

모바일은 하단 고정 내비게이션, PC는 좌측 사이드바를 사용한다. 기기 종류를 묻지 않고 화면 폭으로 바뀐다. 로그인 계정과 로그아웃 동작도 현재 레이아웃 안에서 확인할 수 있다.

## 3. Google 로그인과 계정

- `Google로 계속하기`를 누르면 Google의 계정 선택·동의 화면으로 이동한다.
- Google 인증이 끝나면 허용된 사이트 주소로 돌아와 로그인 세션을 시작한다.
- 별도의 이메일·비밀번호 회원가입, 인증 메일, 비밀번호 재설정 화면은 제공하지 않는다.
- 인증 세션은 Supabase 클라이언트가 관리한다.
- 로그아웃하면 현재 브라우저의 계획 화면을 닫고 로그인 화면으로 돌아간다. 다른 기기의 로그인 세션은 유지된다.
- 계획 조회·생성·변경·삭제는 로그인한 사용자의 `user_id`에만 허용된다.

Google 이외의 로그인 공급자, 닉네임·프로필 편집, 계정 삭제 UI는 현재 제공하지 않는다.

## 4. 내 계획표

### 빈 상태

- 로그인한 계정에 계획이 없으면 `아직 계획이 없습니다.`를 표시한다.
- `계획 만들기` 버튼으로 작성 탭을 연다.
- 검술·명상·서예 같은 시안용 일정은 기본 데이터로 넣지 않는다.

### 주간 보기

- 월요일부터 일요일까지 한 주를 표시한다.
- 이전 주·다음 주로 이동할 수 있다.
- 06:00부터 24:00까지 세로 시간표를 보여 준다.
- `30분 / 1시간`은 화면의 눈금 높이만 바꾼다.
- 모바일에서는 넓은 주간표가 카드 내부에서 가로·세로 스크롤된다.
- 일정 카드를 누르면 날짜, 시간, 상태, 메모와 삭제 버튼이 있는 상세 시트가 열린다.
- 반복 일정의 삭제 버튼은 `반복 계획 전체 삭제`로 표시하며 모든 회차를 함께 삭제한다.

### 오늘 보기

- 오늘 발생하는 일정만 시간순으로 보여 준다.
- `표 / 원` 보기로 전환할 수 있다.
- 표 보기에서는 종료되어 미확인이 된 일정에 `완료했어 / 못 했어` 버튼이 나온다.
- 원형 보기는 00시부터 23시까지의 작은 시간 숫자, 24시간 안의 일정 구간과 텍스트 범례를 보여 준다.
- 오늘의 전체 계획 수, 완료 수, 미확인 수를 간단히 표시한다.

## 5. 계획 만들기

### 직접 작성

입력값:

- 계획 이름
- 날짜
- 시작·종료 시간
- 반복 요일(선택)
- 분류 색상
- 메모(선택)

종료 시간은 시작 시간보다 늦어야 한다. 반복 요일을 고르면 기준 날짜 이후 해당 요일에 같은 일정 행이 계속 표시된다. 반복 종료일은 현재 지원하지 않지만, 각 발생 날짜의 완료·미완료 상태는 서로 독립적으로 저장된다.

저장하면 로그인한 사용자의 Supabase 계획 한 건을 만들고 내 계획표 탭으로 돌아간다. 저장에 실패하면 입력 내용을 브라우저 계획으로 대신 저장하지 않는다. 오류와 재시도 안내를 표시한다.

### 자동 생성

입력값:

- 할 일 이름과 총 소요 분
- 시작일과 마감일
- 가능한 요일
- 공통 가능한 시작·종료 시간
- 하루 최대 1–4시간
- 계획 단위 30분 또는 1시간

자동 생성기는 입력 순서의 할 일을 선택 기간에 가능한 날짜로 고르게 분배한다. 가능한 시간이 부족하면 배치하지 못한 분량을 알려 준다.

현재 동작:

- 화면은 `할 일과 총 시간 → 가능한 날짜와 시간 → 미리보기와 저장` 순서를 세 단계로 안내한다.
- 입력 조건을 바꾸면 이전 미리보기를 비워, 바꾸기 전 결과를 실수로 저장하지 않게 한다.
- 기존에 저장된 일정과의 충돌은 검사하지 않는다.
- 생성 결과는 읽기 전용 미리보기이며 항목별 수정·삭제는 없다.
- 화면에는 미리보기 최대 12개를 보여 주지만 저장 버튼은 생성된 전체 항목을 저장한다.
- 생성된 일정은 Supabase에 한 건씩 순서대로 저장한다.
- 일괄 트랜잭션이 아니므로 중간 실패 시 앞서 저장된 일부 일정은 남을 수 있다.
- 중간 실패 뒤에는 이미 저장된 항목을 미리보기에서 빼고 남은 일정만 다시 저장할 수 있게 한다.
- 실패한 나머지 일정을 `localStorage`에 대신 저장하거나 자동으로 재전송하지 않는다.

## 6. 일정 상태와 캐릭터 반응

화면 상태:

- `예정`: 종료 전
- `미확인`: 종료 후 사용자가 아직 판정하지 않음
- `완료`
- `미완료`

`예정` 일정은 판정할 수 없다. 시간이 지나면 화면에서 `미확인`으로 계산되며 자동으로 `미완료`가 되지 않는다. 반복 일정은 선택한 발생 날짜만 완료 또는 미완료로 판정되고, 다른 날짜의 같은 반복 일정은 바뀌지 않는다. 비반복 일정은 계획 행의 기존 상태를 사용한다. 현재 UI는 한 번 완료 또는 미완료로 판정한 뒤 다시 정정하는 기능을 제공하지 않는다.

판정하면 현재 브라우저 세션 안에서 청명 → 백천 → 유이설 → 조걸 → 윤종 순으로 한 명씩 등장한다. 순번과 등장 인물은 저장하지 않아 새로고침하면 청명부터 다시 시작한다.

### 확정 대사

| 인물 | 완료 | 미완료 |
|---|---|---|
| 청명 | `오, 좀 하는데?` | `어디서 할 일을 빼먹고 있어? 뒈지려고?` |
| 백천 | `잘했다. 네가 정말 자랑스럽다.` | `네가 처한 상황이 지금 한가해 보이냐? 빨리빨리 해!` |
| 유이설 | `할 일은 잘하네. 착해.` | `느려. 빨리 해.` |
| 조걸 | `이건 청명이도 인정하겠는데?` | `앞으로 잘해! 청명이한테 찍힌다.` |
| 윤종 | `정말 고생 많았다. 네가 잘할 줄 알았다.` | `도망친다고 될 일이 아니다. 다음에는 꼭 하거라.` |

오늘의 미확인 일정이 있으면 화산오검 다섯 인장을 함께 표시하고 다음 문구를 쓴다.

> `뭐야, 왜 안 왔어?`

사진은 사용하지 않고 이름의 첫 글자를 넣은 인장으로 표현한다.

## 7. 수련 기록

기록 탭 상단은 `완료했어 / 못 했어` 판정을 남기면 기록이 자동으로 쌓인다는 점을 먼저 설명한다. 계획은 있지만 판정된 회차가 하나도 없으면 0% 통계를 늘어놓지 않고 기록을 남기는 방법과 `내 계획표 보기` 버튼을 보여 준다.

판정 기록이 있으면 비반복 계획과 반복 계획의 발생 회차를 기준으로 다음을 표시한다.

- 확인한 계획 완료율과 판정 횟수
- 연속 완료 일수, 확인 대기 개수, 미완료 개수
- 최근 발생일 기준 판정 회차 최대 6개
- 이번 주에 완료한 발생 회차 1개마다 1송이가 피는 매화 시각화

정보 순서는 `한눈에 보기 → 최근 계획 결과 → 이번 주 매화`다.

계산:

- 완료율 분모는 사용자가 판정한 발생 회차의 `완료 + 미완료`만 포함한다.
- 예정과 미확인은 완료율 분모에서 제외한다.
- 연속 달성과 미확인 개수는 최대 최근 365일의 발생 회차를 만든 뒤 계산한다.
- 연속 달성은 일정이 있는 날짜만 역순으로 보며, 모두 완료된 날짜를 센다.
- 미완료 또는 미확인이 있는 날짜에서 연속 기록이 끊긴다.
- 오늘에 예정 일정만 있으면 오늘을 건너뛰고 이전 기록부터 계산한다.
- 이번 주 매화는 현재 주에 `완료`로 판정한 발생 회차 수만큼 한 송이씩 핀다.

월간 통계와 사용자 지정 기간 필터는 현재 제공하지 않는다.

## 8. 저장, 동기화, 기존 계획 가져오기

### 현재 계획 저장

- 로컬 개발, OpenAI Sites, Vercel 모두 Supabase의 `plans` 테이블을 단일 저장소로 사용한다.
- 각 계획은 Supabase Auth의 사용자 ID에 연결된다.
- Row Level Security(RLS)가 로그인한 사용자에게 자신의 행만 조회·생성·변경·삭제하도록 제한한다.
- 같은 계정으로 로그인하면 다른 기기와 브라우저에서도 같은 계획을 불러온다.
- 계획이 많아도 Supabase 반환 한도에 잘리지 않도록 페이지 단위로 전체를 불러온다.
- 네트워크나 Supabase 오류가 나면 오류와 재시도 동작을 표시한다.
- 새 계획이나 상태 변경을 브라우저 `localStorage` 또는 D1에 자동 폴백하지 않는다.

### 기존 계획 가져오기

이전 버전의 계획은 새 계정 저장소와 자동으로 합치지 않는다.

- 로그인 뒤 사용자가 `기존 계획 가져오기`를 직접 눌러야 시작한다.
- 현재 사이트 origin의 Vercel `localStorage` 계획과, 같은 브라우저의 과거 `maewha-client-id`로 조회할 수 있는 Sites D1 계획이 대상이다. D1 계획은 500행 단위로 끝까지 조회한다.
- 가져오기는 계획을 한 건씩 Supabase에 순서대로 추가한다.
- 이미 같은 내용의 계획이 있으면 중복 추가를 피한다.
- 중간 실패 시 일부만 가져와질 수 있으며, 남은 항목은 오류 안내 뒤 다시 시도할 수 있다.
- 가져온 뒤에도 원래 `localStorage`와 D1 계획을 자동 삭제하지 않는다.
- 기존 계획과 Supabase 계획의 판정 상태를 자동 병합하지 않는다.
- 다른 Vercel 도메인이나 브라우저 프로필의 `localStorage`는 브라우저 보안상 현재 사이트에서 읽을 수 없다.

D1과 `/api/plans`는 이 과도기 가져오기의 기존 계획 읽기용으로만 유지한다. 새 계획 저장, 판정, 삭제의 기준 저장소로 사용하지 않는다.

### 저장하지 않는 화면 상태

- 30분/1시간
- 주간/오늘
- 표/원
- 기준 주
- 자동 생성 미리보기
- 캐릭터 반응 순번

## 9. 현재 범위 밖

- 친구, 응원, 순위표
- 이메일·비밀번호 로그인과 Google 이외의 로그인 공급자
- 프로필 편집
- 계정 삭제 UI
- 캐릭터 사진과 웹툰 원본 이미지
- 일정 편집 및 판정 정정
- 자동 생성 미리보기 편집
- 기존 일정 충돌 회피
- 자동 계획과 기존 계획 가져오기의 원자적 일괄 저장
- 기존 저장소와 Supabase 계획의 자동 병합·자동 삭제
- 월간·기간별 상세 통계
- 알림, 외부 캘린더 연동, 드래그 앤 드롭
- 오프라인 작성과 나중 동기화

## 10. MVP 승인 기준

- 로그아웃 상태에서 `Google로 계속하기` 진입점을 확인할 수 있다.
- Google 인증 뒤 원래 사이트로 돌아와 로그인 상태가 된다.
- 로그인한 뒤 빈 상태와 세 탭이 보인다.
- 직접 작성한 계획이 Supabase에 저장되고, 같은 계정으로 새로고침하거나 다른 기기에서 로그인해 다시 보인다.
- 다른 계정에서는 해당 계획을 조회·변경할 수 없다.
- 자동 생성 미리보기, 부족 분량 경고, 순차 저장이 작동한다.
- 저장 오류가 새 브라우저 계획 생성으로 조용히 폴백되지 않고 오류와 재시도를 제공한다.
- 기존 계획은 사용자가 가져오기 버튼을 누른 뒤 순차적으로 복사되며 원본은 삭제되지 않는다.
- 주간/오늘, 30분/1시간, 표/원이 실제로 전환된다.
- 종료된 일정은 미확인으로 보이고 완료·미완료 판정과 대사가 작동한다.
- 반복 계획 판정은 선택한 발생 날짜에만 적용된다.
- 기록 탭이 발생 회차 기준 통계를 표시한다.
- 친구 메뉴와 예시 수련 일정, 원격 캐릭터 이미지는 없다.
